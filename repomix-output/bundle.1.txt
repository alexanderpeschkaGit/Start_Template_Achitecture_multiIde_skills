# Shared Instructions & IDE Adapters

This repository supports multiple AI IDEs and autonomous agents. Project policy has one source of truth; IDE files may add only the minimal capability translation required by their host.

## Routing Tree

Adapters must not duplicate project policy or hard-code user-machine paths.

`[IDE Dotfile]` ──points to──> `AGENTS.md` ──delegates to──> `[.agents/rules/*.md & WORKFLOWS.md]`

1. **IDE adapters (e.g., `.clinerules`, `.cursor/rules/agents.mdc`, `KIMI.md`):** Point to the canonical instructions and may translate agent capabilities such as subagents or rate limits. They do not redefine project policy.
2. **`AGENTS.md` (Root):** The canonical entry point. It enforces host constraints (Windows/PowerShell) and handles global code quality limits.
3. **`.agents/rules/*.md`:** Domain-specific rules loaded dynamically via progressive disclosure based on the files the AI is editing.
4. **`.agents/WORKFLOWS.md`:** Global routing for `#tags` and `/commands`.

## Add a New IDE

When integrating a new AI IDE, create its system prompt file and use this template. Add only adapter-specific capability translation below it when needed.

```markdown
This repository uses `AGENTS.md` in the repository root as the canonical instruction file. Read and follow it before performing any task.
For workflow commands, read `.agents/WORKFLOWS.md` and then the referenced repository-local skill.
```

## Unified 3-Tier Model Routing (`#plan`, `#exec`, `#exec-wave`)

All execution workflows follow a **Flash-First, Pro-on-Demand** tiering model based on the 1–10 complexity score assigned per step/batch:

| Tier                      | Complexity Score | Target Scope                                                                       | Subagent Model (`Mode A`)   |
| :------------------------ | :--------------- | :--------------------------------------------------------------------------------- | :-------------------------- |
| **Tier 1 (`FLASH_LITE`)** | `1–3`            | Copy updates, simple type exports, config tweaks, minor CSS/Tailwind (<300 lines)  | `flash_lite`                |
| **Tier 2 (`FLASH`)**      | `4–6`            | Standard component/hook batches (<= 3–4 files, clear interfaces, <500 lines)       | `flash` _(Default)_         |
| **Tier 3 (`PRO`)**        | `7–10`           | Cross-file Zustand state, SSR/Hydration, Audio/Video lifecycles, files >=500 lines | `pro` _(+ Reviewer at >=8)_ |

- **Auto-Escalation Rule:** If a Tier 1 (`flash_lite`) or Tier 2 (`flash`) step fails validation (`npm run lint` / `npm test`) and survives **one** targeted diagnostic repair attempt, escalate that specific step/batch immediately to Tier 3 (`pro`).
  - **Zero-PRO Token Guard (`--no-pro` / `--no-pro-escalation`):** If `--no-pro` is explicitly flagged or budget mode is active, automatic PRO escalation is suppressed. The agent halts in **Graceful Pause (Dirty Inspection)** after the single repair attempt to preserve modified files without spending PRO tokens.

For `Score >= 8` Red-Team audits, spawn a read-only auditor with `TypeName: 'research'`, `Model: 'pro'`, and `Role: 'Red-Team Auditor'` returning a compact 2-point audit report (`Verdict`, `Findings`).
   - **Kilo Code v7:** Its project `kilo.jsonc` uses an OpenCode-compatible configuration shape. Kilo loads root `AGENTS.md` automatically; list `.agents/WORKFLOWS.md` in the `instructions` array. Map `invoke_subagent` model tiers to Kilo's native `Task` tool and the configured `agent` identifiers (`flash_lite`, `flash`, `pro`, and `research`).

Treat Tier 1–2 as a **behavior** contract (apply `.agents/skills/flash/SKILL.md` inside the subagent or inline). ## Self-Contained Lockstep Dependency Group

Six files form one atomic documentation unit. A change to the tier table, the diff-audit protocol, the handoff link labels, or the subagent prompt contract in any one of them must be verified for parity in all of them within the same batch:

`.agents/rules/multi-ide-setup.md` · `.agents/skills/plan/SKILL.md` · `.agents/skills/exec/SKILL.md` · `.agents/skills/exec-wave/SKILL.md` · `.agents/skills/delegate/SKILL.md` · `.agents/skills/solve/SKILL.md`

- **No partial updates:** Never stage a lockstep change while another group member still documents the previous tier split, audit protocol, or link-label convention.
- **Parity probe:** `Select-String -Path .agents/skills/*/SKILL.md -Pattern 'flash_lite'` must match every execution skill in the group.

## Combo Anti-Phantom Diff Audit

Every subagent return — and every lockstep commit — requires both probes, because neither one alone is complete:

```powershell
git --no-pager diff --name-only
git --no-pager status --porcelain
```

`git diff --name-only` omits untracked files; `git status --porcelain` alone blurs the modified/created distinction. Reconcile the **union** of both outputs against the plan's File Inventory.

- **Phantom reporting:** An assigned file absent from the union means the batch did not actually touch it. Reject the subagent's `SUCCESS` as `INCOMPLETE_TASK` / `PHANTOM_REPORTING` and run a targeted completion pass before staging anything.

## Shared Cross-IDE Working State (`.tmp/`)

For workflows that maintain execution context or reports across IDE boundaries (such as `#solve` and `#delegate`), the living plan and final change report are stored at `.tmp/solve_report.md` (gitignored). This ensures that any editor or IDE can open and display the report with standard `file:///` markdown links without depending on IDE-internal storage directories.

## Acceptance & Audit Criteria

1. **Canonical Root Reference:** All IDE adapter dotfiles (.clinerules, .cursor/rules/agents.mdc, KIMI.md, GEMINI.md) strictly point to `AGENTS.md` as the single canonical source of truth.
2. **3-Tier Model Table Parity:** The tier table reflects `flash_lite` (Score 1–3), `flash` (Score 4–6), and `pro` (Score 7–10) consistently across all workflow definitions.
3. **Subagent Type Identity:** Implementation subagents use abstract `TypeName: 'self'` (Mode A: `invoke_subagent`; Mode D: Cursor `Task` / `generalPurpose`) with host-appropriate model constraints; read-only auditors use abstract `TypeName: 'research'` (Mode A: `research`; Mode D: `explore`).
4. **IDE-Independent Storage:** Living execution plans and cross-IDE handoffs strictly write to `.tmp/` (gitignored), never IDE-internal state storage.
5. **Cursor Adapter Parity:** `.cursor/rules/agents.mdc` documents Mode D (not Mode C) and must not instruct agents to call `invoke_subagent` or pass `flash_lite`/`flash`/`pro` as Cursor model slugs.

# Deep-Refactor Workflow (`#deep-refactor`)

**Purpose:** Safely decompose monolithic files into focused hooks (`src/hooks/`), pure utilities (`src/utils/` or `*Utils.ts`), types (`*.types.ts`), and leaf components without changing observable runtime behavior.

**Boundary vs. `#refactor`:** `#refactor` owns structure-preserving changes inside the current architecture (extractions, type tightening, duplication removal, files under ~300 lines). `#deep-refactor` is the dedicated path for decomposing monolithic files (>= 300 lines) with 100% behavior parity — never route that work through `#refactor`.

---

## 1. Execution Modes (Choose Based on Context)

### Mode A: Interactive Batch Mode _(Default when exploring & refactoring live)_

- **Limit:** Maximum **3 implementation files** per batch (test files `*.test.ts` and docs `*.md` do not count toward the limit).
- **Validation per Batch:** Run `npm run lint` and `npm test` after each batch and create a checkpoint commit on `preview`.
- **Handoff Checkpoint:** Pause after Batch 3 to offer a concise session-handoff summary unless Auto-Pilot is active.
- **Recommended Model:** `PRO` or `Flash (High Thinking)`.

### Mode B: One-Shot Blueprint Mode _(Triggered by `#oneshot`, "alle auf einmal", or when a complete plan/code blueprint is provided)_

- **No Batch/File Limit:** Write all new and updated modules in a **single pass** without intermediate stops.
- **Single Validation Pass:** Run `npx prettier --write <scoped-files>`, `npm run lint`, `npm test`, and `npm run check` **once** after all files are written.
- **Recommended Model:** `Flash (Low or Medium Thinking)` for maximum speed when applying pre-verified code. When using Flash, strictly follow the Single-Action Protocol from `flash/SKILL.md`.

---

## 2. Non-Negotiable Guardrails (Both Modes)

1. **100% Behavior & Export Parity:**
   - Preserve all public props, named/default exports, and re-exported types so parent callers require zero changes unless explicitly in scope.
   - Preserve all DOM querySelector classes (e.g., `.zoom-media-container`, `.media-zoom-target`, `[data-video-controls]`), inline math (letterbox/pillarbox geometry), event capture order (`onPointerDownCapture` vs `onClickCapture`), and platform keys (`ios-stable-video`).
   - Keep `useEffect`, `useMemo`, and `useCallback` dependency arrays semantically identical.
2. **Dirty Working Tree Protection:**
   - Run `git status --short` in Preflight (B0).
   - Never stage, revert, format, or overwrite pre-existing modified or untracked user files.
   - Never use `git add .`, `git reset`, `git checkout`, or `git clean`. Always stage explicit file paths.
3. **Branch & Remote Safety:**
   - Commit only on `preview` or a dedicated feature branch (`never` on `main`/`master`).
   - Never run `git push` automatically.

---

## 3. Standard Execution Phases

1. **Phase 0 (Preflight):** Check `git status --short`, inspect target file + all callers, record baseline for `npm run lint` and `npm test`.
2. **Phase 1 (Pure Utils & Types):** Extract `*.types.ts` and pure helper functions (`*Utils.ts`) + optional unit test (`*Utils.test.ts`).
3. **Phase 2 (Custom Hooks):** Extract state, timers, DOM observers, and event capture handlers into `src/hooks/<domain>/` and update `index.ts` barrel exports.
4. **Phase 3 (Leaf Components & Orchestrator):** Extract isolated JSX sub-trees into leaf components and reduce the main component to a clean orchestrator (<200 lines).
5. **Phase 4 (Documentation Sync — Mandatory):** Check whether `AGENTS.md` or any file in `.agents/rules/` (`core-react-state.md`, `mobile-touch.md`, `video-audio-media.md`, `styling-ui.md`, `cloudflare-architecture.md`) references the refactored file and update the architecture notes accordingly.
6. **Phase 5 (Final Verification & Commit):** Run scoped Prettier, `npm run lint`, `npm test`, `npm run check`, bump `package.json` patch version once (if `package.json` is clean), commit on `preview`, and output a concise Completion Report (line-count delta + parity checklist).
</file>

# Exec-Wave Workflow (`#exec-wave`)

**Purpose:** Execute multi-batch architectural plans (`plans/Batch_*.md`) organized into serial phases and parallel waves while keeping the main Coordinator agent's context window minimal and routing each batch to the most cost- and speed-effective model tier.

---

## Core Execution Protocol

1. **Read Only the Master Roadmap & Resolve Batch Tiers:**
   - Read the referenced roadmap file (e.g., `plans/00_MASTER_ROADMAP.md`) to identify the execution topology (Serial Phases vs. Parallel Waves) and each batch's complexity metadata (`[Score: X/10 | Tier: FLASH_LITE | FLASH | PRO]`).
   - **CRITICAL:** The Coordinator MUST NOT read the full target source files or implement code inline in the main conversation (unless operating in a Mode C Single-Agent IDE without subagents; Mode D Cursor may use `Task` isolation instead — see Section 5).
   - **3-Tier Per-Batch Model Selection (Flash-First Strategy):** Triggering `#exec-wave` / `/exec-wave` (or `#wave-exec` / `/wave-exec`) constitutes explicit user authorization to pass `Model: 'flash_lite' | 'flash' | 'pro'` to `invoke_subagent` (overriding default `'inherit'` in Mode A):
     - **Tier 1 (`flash_lite` — Score 1–3):** Trivial/mechanical batches (copy, simple types, static config, minor Tailwind/CSS in files <300 lines, strictly capped at <= 2–3 files). Auto-Upgrade Guard: If a batch tagged `flash_lite` touches 4 or more files, the Coordinator MUST automatically escalate its Model to `flash` upon invocation to prevent subagent truncation and phantom reporting.
     - **Tier 2 (`flash` — Score 4–6, Default):** Standard scoped implementation batches (<= 3–4 files, clear interfaces, files <500 lines). If a batch has no explicit tier tag and touches only files <500 lines, default to `flash`.
     - **Tier 3 (`pro` — Score 7–10 or Unsliced Files >=500 Lines):** Complex cross-file state refactors (Zustand, SSR/Hydration, Audio/Video lifecycles), unsliced files >=500 lines (`AGENTS.md` Mandatory Pro Decomposition), or high blast-radius architecture batches. **Flash Wave Exemption:** If `#flash` is specified in the trigger or roadmap, batches touching >=500 line files route to `flash` instead of `pro`, provided the batch File Inventory <= 3 files and complexity score <= 6.

2. **Serial Phase Execution:**
   - For a serial batch (e.g., `plans/Batch_01_*.md`), spawn a single subagent via `invoke_subagent` using the batch's resolved tier:
     - **TypeName:** `self`
     - **Model:** `flash_lite` (Score 1–3) | `flash` (Score 4–6) | `pro` (Score 7–10)
     - **Role:** `Batch Executor`
     - **Prompt:** _"Read the execution plan at `<relative-path-to-batch.md>` and implement all file changes strictly as specified, adhering to `.agents/skills/flash/SKILL.md` stability rules. # Repomix Codebase Chunking & Bundler Workflow

Pack the repository into semantically partitioned chunks with a strict maximum limit of **130,000 characters per chunk** (`repomix-output/bundle.*.txt`), designed for LLM context windows, multi-agent analysis, or external AI platforms.

## Core Architecture & 130k Partitioning Strategy

1. **Semantic Grouping (Preserving Code Context):**
   Repomix uses top-level directory boundaries to group files logically. A single file or function is **never sliced down the middle** across chunks.
2. **Buffer Margin for 130,000 Characters:**
   In `repomix.config.json`, `splitOutput` is set to `120000` (bytes). This 10,000-character safety margin accounts for XML wrapping, file headers, directory trees, and token metrics, ensuring the final files remain strictly `<= 130,000 characters`.
3. **Automated Audit:**
   Every bundling run is immediately verified by `scripts/patches_and_tests/repomix-audit.ps1`, reporting the exact character count, byte size, and pass/fail status per chunk.

# Troubleshooting & Edge Cases (`zip-clean`)

## 1. Locked Files
If an editor or background server has locked a file, PowerShell's `.NET ZipArchive` might raise an `IOException` (`The process cannot access the file because it is being used by another process`).
- **Fix:** Stop active dev servers (`npm run dev`) or test runners before running `zip-clean`.

## 2. Long Path Names on Windows
Windows path limits (MAX_PATH = 260 characters) can sometimes affect deep folder structures.
- `zip-clean.ps1` uses .NET `[System.IO.Compression.ZipFile]` which supports long paths natively when paths are normalized.
- If you encounter a MAX_PATH issue, specify an `-OutputPath` near the drive root (e.g., `C:\temp\archive.zip`).

## 3. Accidental Inclusion of the ZIP Itself
When creating an archive inside the repository folder (e.g., `Y:\repo\archive.zip`), a naive file search might attempt to zip `archive.zip` while it is being written, causing recursion or corruption.
- `zip-clean.ps1` automatically excludes `$resolvedOutput` by comparing absolute paths before archiving, preventing this issue.

## 4. Cross-Platform ZIP Separators
Windows standard paths use backslashes (`\`), but ZIP file specifications require entry keys to use forward slashes (`/`).
- `zip-clean.ps1` explicitly converts relative paths to `/` when creating archive entries:
  ```powershell
  $entryName = $rel.Replace('\', '/')
  ```
  This ensures compatibility when opening the resulting archive on Linux, macOS, Android, or cloud servers.

## 5. Secret Protection
`git ls-files --exclude-standard` strictly obeys `.gitignore`, and `-AdditionalExcludes` now defaults to `@('*.zip', '*.tmp', '.env*', '*.pem', '*.key')`, so stray secrets are filtered even when a rule is missing from `.gitignore`.
- For other secret naming schemes (e.g. `*.p12`, `*.pfx`, `id_rsa*`), append patterns: `-AdditionalExcludes @('*.zip','*.tmp','.env*','*.pem','*.key','*.p12','id_rsa*')`.
- The exclude list is a safety net, not a replacement for ignore rules — always add the file to `.gitignore` as well.

## 6. Non-Git Fallback Enumeration
When `git ls-files` yields nothing, the script falls back to `Get-ChildItem -Recurse -File`.
- The fallback skips `.git`, `node_modules`, `dist`, `.wrangler`, `.tmp`, and every `repomix*` directory (e.g. `repomix-output/`) before `-AdditionalExcludes` runs, so it never packages dependencies, build output, local Wrangler state, or bundler dumps. Root-level runner files (`repomix.ps1`, `repomix.bat`, `repomix.config.json`) remain packaged.
- If a new heavy directory still appears in a fallback archive, add it to `$excludedDirs` in `zip-clean.ps1` or extend `-AdditionalExcludes`.

    Additional glob patterns or filenames to exclude (e.g., @('*.zip', '*.tmp', '.env*')).

.PARAMETER DryRun
    If set, lists files that would be included and outputs file counts without creating the ZIP.

.PARAMETER Force
    Overwrite output ZIP if it already exists.

.EXAMPLE
    .\zip-clean.ps1
    Creates a timestamped zip in the repository root.

.EXAMPLE
    .\zip-clean.ps1 -OutputPath "C:\Backups\Portfolio.zip" -Force

.EXAMPLE
    .\zip-clean.ps1 -DryRun
#>

[CmdletBinding()]
param (
    [Parameter(Position = 0)]
    [string]$OutputPath,

    [Parameter()]
    [ValidateSet('WorkingTree', 'Head', 'TrackedOnly')]
    [string]$Mode = 'WorkingTree',

    [Parameter()]
    [string]$Prefix = '',

    [Parameter()]
    [string[]]$AdditionalExcludes = @('*.zip', '*.tmp', '.env*', '*.pem', '*.key'),

    [Parameter()]
    [switch]$DryRun,

    [Parameter()]
    [switch]$Force
)

Set-StrictMode -Off
$ErrorActionPreference = 'Stop'

# 1. Locate repository root
$repoRootRaw = (git rev-parse --show-toplevel 2>$null)
if (-not $repoRootRaw -or -not (Test-Path $repoRootRaw)) {
    $repoRoot = (Get-Item (Get-Location).Path).FullName
    Write-Warning "Not inside a detected git repository. Working in: $repoRoot"
} else {
    $repoRoot = (Get-Item $repoRootRaw).FullName
}

# 2. Extract repository name & optional version from package.json
$repoName = Split-Path $repoRoot -Leaf
$version = ""
$pkgJsonPath = Join-Path $repoRoot "package.json"
if (Test-Path $pkgJsonPath) {
    try {
        $pkg = Get-Content -Raw -Path $pkgJsonPath | ConvertFrom-Json
        if ($pkg.version) {
            $version = "v$($pkg.version)_"
        }
    } catch {
        # ignore parse errors
    }
}

# 3. Determine default OutputPath
$timestamp = Get-Date -Format "yyyyMMdd_HHmmss"
if (-not $OutputPath) {
    $zipFileName = "${repoName}_${version}${timestamp}.zip"
    $OutputPath = Join-Path $repoRoot $zipFileName
}

$resolvedOutput = [System.IO.Path]::GetFullPath($OutputPath)
$outputFileName = [System.IO.Path]::GetFileName($resolvedOutput)

# 4. Handle existing output file
if ((Test-Path $resolvedOutput) -and -not $Force -and -not $DryRun) {
    throw "Target archive already exists: $resolvedOutput. Use -Force to overwrite."
}

Write-Host "==========================================" -ForegroundColor Cyan
Write-Host " Clean ZIP Generator (Excluding .gitignore)" -ForegroundColor Cyan
Write-Host "==========================================" -ForegroundColor Cyan
Write-Host "Repository Root : $repoRoot"
Write-Host "Archive Mode    : $Mode"
Write-Host "Target Archive  : $resolvedOutput"
if ($Prefix) { Write-Host "Archive Prefix  : $Prefix" }

# 5. Gather file list respecting .gitignore
Push-Location $repoRoot
try {
    $files = @()
    if ($Mode -eq 'Head') {
        # Committed files at HEAD
        $files = git ls-tree -r --name-only HEAD 2>$null
    } elseif ($Mode -eq 'TrackedOnly') {
        # Tracked files (working tree state)
        $files = git ls-files --cached 2>$null
    } else {
        # WorkingTree mode: tracked + untracked non-ignored files
        $files = git ls-files --cached --others --exclude-standard 2>$null
    }

    if (-not $files -or $files.Count -eq 0) {
        Write-Warning "No files returned by git command. Checking directory fallback..."
        $excludedDirs = @('.git', 'node_modules', 'dist', '.wrangler', '.tmp')
        $files = Get-ChildItem -Recurse -File | Where-Object {
            $relative = $_.FullName.Substring($repoRoot.Length).TrimStart('\')
            $segments = $relative -split '[\\/]'
            $inExcludedDir = $false
            for ($i = 0; $i -lt ($segments.Count - 1); $i++) {
                if ($excludedDirs -contains $segments[$i] -or $segments[$i] -like 'repomix*') { $inExcludedDir = $true; break }
            }
            (-not $inExcludedDir)
        } | ForEach-Object {
            $_.FullName.Substring($repoRoot.Length).TrimStart('\')
        }
    }
} finally {
    Pop-Location
}

# 6. Filter file list
$filteredFiles = [System.Collections.Generic.List[string]]::new()
$totalRawBytes = 0

foreach ($rel in $files) {
    if (-not $rel) { continue }

    # Normalize slashes for comparison
    $normalizedRel = $rel.Replace('/', '\')
    $fullPath = Join-Path $repoRoot $normalizedRel

    # Check existence
    if (-not (Test-Path $fullPath -PathType Leaf)) {
        continue
    }

    # Exclude target output file if within repository tree
    if ([string]::Equals($fullPath, $resolvedOutput, [System.StringComparison]::OrdinalIgnoreCase)) {
        continue
    }

    # Exclude additional patterns
    $fileName = [System.IO.Path]::GetFileName($fullPath)
    $skip = $false
    foreach ($pattern in $AdditionalExcludes) {
        if ($fileName -like $pattern -or $normalizedRel -like $pattern) {
            $skip = $true
            break
        }
    }
    if ($skip) { continue }

    $filteredFiles.Add($rel)
    $item = Get-Item $fullPath
    $totalRawBytes += $item.Length
}

$rawSizeMB = [math]::Round($totalRawBytes / 1MB, 2)
Write-Host "Matched Files   : $($filteredFiles.Count) files ($rawSizeMB MB uncompressed)" -ForegroundColor Green

# 7. Dry run check
if ($DryRun) {
    Write-Host "`n[DRY RUN] The following files would be packaged:" -ForegroundColor Yellow
    $displayLimit = [math]::Min($filteredFiles.Count, 25)
    for ($i = 0; $i -lt $displayLimit; $i++) {
        Write-Host "  + $($filteredFiles[$i])"
    }
    if ($filteredFiles.Count -gt 25) {
        Write-Host "  ... and $($filteredFiles.Count - 25) more files." -ForegroundColor DarkGray
    }
    Write-Host "`nDry run complete. No ZIP file was created." -ForegroundColor Yellow
    exit 0
}

# 8. Create ZIP archive using .NET ZipArchive
$sw = [System.Diagnostics.Stopwatch]::StartNew()

Add-Type -AssemblyName System.IO.Compression
Add-Type -AssemblyName System.IO.Compression.FileSystem

$parentDir = Split-Path $resolvedOutput -Parent
if ($parentDir -and -not (Test-Path $parentDir)) {
    New-Item -ItemType Directory -Path $parentDir -Force | Out-Null
}

if (Test-Path $resolvedOutput) {
    Remove-Item $resolvedOutput -Force
}

$zip = [System.IO.Compression.ZipFile]::Open($resolvedOutput, [System.IO.Compression.ZipArchiveMode]::Create)

try {
    $count = 0
    foreach ($rel in $filteredFiles) {
        $fullPath = Join-Path $repoRoot $rel.Replace('/', '\')
        
        # Zip entry paths MUST use forward slashes for universal compatibility
        $entryName = $rel.Replace('\', '/')
        if ($Prefix) {
            $trimmedPrefix = $Prefix.TrimEnd('/')
            $entryName = "$trimmedPrefix/$entryName"
        }

        # Write to archive with optimal compression
        [System.IO.Compression.ZipFileExtensions]::CreateEntryFromFile(
            $zip,
            $fullPath,
            $entryName,
            [System.IO.Compression.CompressionLevel]::Optimal
        ) | Out-Null

        $count++
        if ($count % 50 -eq 0 -or $count -eq $filteredFiles.Count) {
            Write-Progress -Activity "Compressing clean archive" -Status "$count / $($filteredFiles.Count) files" -PercentComplete (($count / $filteredFiles.Count) * 100)
        }
    }
} finally {
    $zip.Dispose()
    Write-Progress -Activity "Compressing clean archive" -Completed
}

$sw.Stop()

# 9. Verify and output results
if (Test-Path $resolvedOutput) {
    $zipItem = Get-Item $resolvedOutput
    $zipSizeMB = [math]::Round($zipItem.Length / 1MB, 2)
    $ratio = if ($totalRawBytes -gt 0) { [math]::Round((1 - ($zipItem.Length / $totalRawBytes)) * 100, 1) } else { 0 }
    $elapsedSec = [math]::Round($sw.Elapsed.TotalSeconds, 2)

    Write-Host "`n==========================================" -ForegroundColor Green
    Write-Host " ARCHIVE SUCCESSFULLY CREATED" -ForegroundColor Green
    Write-Host "==========================================" -ForegroundColor Green
    Write-Host "File:       $($zipItem.FullName)"
    Write-Host "Size:       $zipSizeMB MB (Saved $ratio% vs $rawSizeMB MB raw)"
    Write-Host "Files:      $count files packaged"
    Write-Host "Duration:   $elapsedSec seconds"
    Write-Host "==========================================" -ForegroundColor Green
} else {
    throw "Failed to create archive at $resolvedOutput."
}
</file>

# Clean ZIP Generator Workflow (`#zip-clean`)

**Purpose:** Package the repository or target project into a clean, distributable ZIP archive that strictly respects `.gitignore` rules, strips `.git/` version-control metadata, excludes destination `.zip` files, and prevents inclusion of build artifacts, dependencies (`node_modules`), secrets, or cache files.

---

## Capabilities & Modes

The skill provides three modes of operation via its bundled PowerShell script `scripts/zip-clean.ps1`:

| Mode | Command Flag | Inclusions | Best For |
| :--- | :--- | :--- | :--- |
| **`WorkingTree`** *(Default)* | `-Mode WorkingTree` | Tracked files + newly added untracked non-ignored files | Sharing current work-in-progress, backups, code handoffs with active uncommitted changes |
| **`Head`** | `-Mode Head` | Strictly committed files at `HEAD` | Clean release packaging, tagged version snapshots |
| **`TrackedOnly`** | `-Mode TrackedOnly` | Tracked files only (reflecting current file content) | Excluding all untracked files while preserving uncommitted edits to tracked files |

---

## Execution Instructions

### Option 1: Automatic Agent Execution (Recommended)

When the user asks to create a zip or triggers `#zip-clean`:

1. **Resolve Destination Path & Naming:**
   - Default filename: `<RepoName>_<Version>_<Timestamp>.zip` in the repository root or parent directory.
   - If user specified a custom path (e.g., `dist/backup.zip` or desktop), resolve the absolute path.

2. **Execute the Bundled Script via PowerShell:**
   ```powershell
   powershell -ExecutionPolicy Bypass -File .agents/skills/zip-clean/scripts/zip-clean.ps1 -Mode WorkingTree
   ```
   *Custom path example:*
   ```powershell
   powershell -ExecutionPolicy Bypass -File .agents/skills/zip-clean/scripts/zip-clean.ps1 -OutputPath "C:\Backups\Portfolio_Clean.zip" -Force
   ```
   *Dry-run example:*
   ```powershell
   powershell -ExecutionPolicy Bypass -File .agents/skills/zip-clean/scripts/zip-clean.ps1 -DryRun
   ```

3. **Verify Archive Integrity:**
   - Confirm file exists and size is greater than 0 bytes.
   - Verify that excluded paths (`node_modules`, `.git`, `.env*`, `dist`, `.wrangler`, `.tmp`, `repomix*`) and secret artifacts (`*.pem`, `*.key`) are absent from the archive entries.
   - Note file count, uncompressed size, compressed size, and elapsed time.

4. **Deliver Concise Summary:**
   Provide the user with:
   - Full path to the created `.zip` file
   - File size (in MB)
   - Number of files packaged
   - Compression ratio achieved

| Parameter | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `-OutputPath` | `string` | `<Repo>_v<Ver>_<Timestamp>.zip` | Target `.zip` path. Relative or absolute. |
| `-Mode` | `string` | `'WorkingTree'` | Selection mode: `'WorkingTree'`, `'Head'`, or `'TrackedOnly'`. |

> [!NOTE] **Non-Git Fallback:** When `git ls-files` returns nothing (no repository, or an empty index), the script enumerates the directory tree directly and skips `.git`, `node_modules`, `dist`, `.wrangler`, `.tmp`, and every `repomix*` directory (such as `repomix-output/`) before applying `-AdditionalExcludes`. Fallback archives therefore never include dependencies, build output, local Wrangler state, or bundler dumps.

- **Forbidden Unix-only tools:** `sed`, `awk`, `grep` (use `Select-String`), `chmod`, `touch`, `cat` (`Get-Content`), `rm` (`Remove-Item`), `cp` (`Copy-Item`), `mv` (`Move-Item`). Prefer PowerShell cmdlets or built-in agent file tools.
- **Line endings:** CRLF is the default; do not force LF-only endings unless `.gitattributes` requires it.

## Code Quality & Modularity Limits

- Apply KISS, practical DRY, and SRP. Use descriptive English identifiers; comments explain *why*, not *what*.
- **File Size & Refactoring Limits:**
  - **300â€“499 lines (Warning):** Warn the user and propose a decomposition (candidate subcomponents, custom hooks, or utility extractions).
  - **500+ lines (Mandatory Decomposition):** Refactor into modular subcomponents (`src/components/`), custom hooks (`src/hooks/`), Zustand stores (`src/store/`), and pure utilities (`src/utils/`), delegating complex decompositions to a `pro` subagent where supported.
- Produce complete, production-ready implementations. Never replace required logic with placeholders such as `// ...`.
- **Version Bumping:** On every checkpoint commit at plan completion, the Coordinator agent increments the patch version in `package.json` (+0.0.1). Subagents are strictly forbidden from modifying `package.json` versions.
- **Script Organization:** Place one-off utility scripts, automated patches, and test scripts in `scripts/patches_and_tests/`. Keep the root repository clean.

## Decision Gate & Interaction Contract

- **Default is action, not a question:** Report progress and pending state as factual statements rather than asking routine confirmation questions.
- **Single-Question Rule:** Ask at most ONE open question per turn. If multiple decisions are pending, bundle them into a single structured query, or run `#grillme` before editing.
- **Hard Stops â€” Always ask:**
  - Actions that leave the local working tree or are irreversible without user prompting: AI-initiated `git push`, pushing to `main`/`production`, deploying to production, git history rewrites, starting persistent background daemons, or deleting user data.
  - Genuine validation failures that survive agreed repair attempts.

## Brand & Configuration SSOT

- **Zero-Hardcoding Contract:** Hardcoded brand names, email addresses, social links, or CDN URLs are forbidden in UI components or server routes. Consume all brand and environment metadata dynamically from `src/config/siteConfig.ts` (`SITE_CONFIG`).

## Rate Limits & Paced Execution (3 RPM)

Kimi Code operates under a strict limit of **3 Requests Per Minute (RPM)**. All tool calls, model inferences, and subagent spawns count against this quota.

To prevent `429 Too Many Requests`:
1. **Pacing Throttle:** Enforce a minimum pause of **25 seconds** between state-changing steps, subagent invocations, and build/validation commands.
2. **Strict Sequential Execution (Concurrency = 1):** Never spawn subagents in parallel. All tasks, delegations, and subagent runs must execute strictly **one at a time**.
3. **Rate-Limit Backoff:** Upon receiving a `429`, immediately pause execution for **40 seconds** before attempting the next request.

## Workflows: Deep Refactor & Multiagent Translation

When executing `#deep-refactor`, `#refactor`, or any workflow that normally uses a concurrent "Scatter-Gather" pattern:

1. **Disable Scatter-Gather:** Replace parallel subagent calls with a **Sequential Queue**:
   - The Coordinator writes individual step plans as usual.
   - Subagents are invoked **one by one**: invoke Subagent 1 → wait for completion → pause 25s → invoke Subagent 2.
2. **Prefer Single-Agent Execution When Feasible:** If file extractions are small or closely coupled, the Main Agent should perform the sequential refactoring steps directly rather than delegating to multiple subagents, drastically conserving RPM quota.
3. **Mega-File Pipeline:** For large files, follow the sequential pipeline (State → Hooks → UI components → Cutover), completing each phase sequentially and running validation only after each full phase rather than after every file change.
4. **Validation Pacing:** Allow the compiler and file system to settle; pause 25 seconds after the last file edit before running `tsc` or `npm run build`.

## Tooling Notes for This Environment

Kimi Code on this machine runs through Git Bash. The project’s `AGENTS.md` recommends PowerShell-native cmdlets for manual use, but Kimi Code’s file tools (`Read`, `Edit`, `Write`, `Glob`, `Grep`) and Bash tool are the preferred way to interact with the repository from this agent. Prefer the dedicated file tools over raw shell commands for file operations; use Bash only for shell semantics (npm, git, build runners) and observe the single-action protocol.
